## Changes in this branch

1. **Match indexing requires a published forecast** (`matchPageIndexable`).
   Fixtures without one stay valid 200 pages with `noindex`, and the match
   sitemap only lists fixtures whose displayed revision has an available market.
2. **Forecast-led match descriptions**, e.g. "… Match result (1X2) estimate:
   Example Home FC win, 54%. See all markets, sources and the locked forecast
   record. Not a guarantee."
3. **Home stays indexable on empty/uncovered days** (still noindex on failed reads
   and while the release gate is closed).
4. **Structured data**: `Organization` + `WebSite` graph on home;
   `BreadcrumbList` on dated archives and canonical match pages. `SportsEvent`
   omitted on purpose (no stored venue → Google `location` error).
5. **`/sitemap-index.xml`** lists `/sitemap.xml` and every shard; robots.txt
   names only the index and no longer queries the database.
6. **No soft 404s**: only real language tags fall back to `/en`; `/faq`, `/app`
   now return 404.
7. **Date-specific H1** on single-day archives ("Football Predictions · Mon, Oct 12, 2026").

## Unresolved blockers

1. **No current fixtures in production** — the live runner and Prisma migrations
   still use MySQL-only SQL, so they cannot target the production MariaDB. Until
   that port lands (or a scheduled sync from the local MySQL is set up), every
   new day is empty and nothing new can be indexed.
2. **Release gate is closed** — production is `noindex` and sitemaps are empty
   until the owner records verified release approval and marks privacy/terms
   ready (`src/server/seo/policy.ts`, `src/domain/*-notice.ts`). Planned launch:
   1 Nov 2026.
3. **www/http redirect chain** — fix at the host: in `~/goalhint.com/.htaccess`,
   above the Passenger block, send `http://` and `www.` straight to
   `https://goalhint.com%{REQUEST_URI}` with one 301.
4. **Accuracy record** — public hit rates need OP-16/OP-17 approval of a frozen
   evaluation protocol; until then only counts and per-match history are shown.
5. **Server response time** — 1.4–4 s TTFB on shared hosting with uncached,
   per-request dynamic pages. Needs profiling on the host (DB latency vs.
   render) before choosing caching.

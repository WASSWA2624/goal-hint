# Goal Hint — App Overview

**Reviewed: 5 November 2026.** Reflects the current source checkout; production deployment and release approval are separate.

## Purpose and users

Goal Hint helps adult football followers browse fixtures, understand predictions, assemble slips, and check outcomes. Members obtain access through subscriptions, trials, or referral days; administrators manage access, payments, and reporting.

It combines a responsive website with a Flutter host for the same experience. Bet placement, stakes, and bookmaker payment processing are outside its scope.

## What has been implemented

Foreground navigation and app work use the shared progress bar beneath the header. Existing content can stay visible while it updates. Background polling and lazy media load quietly.

Desktop and mobile share this menu order: Matches (home), Slips, Builder, Community, Invite friends, Performance, Download app, Contact, Help, Privacy, Terms. Slips, Builder and Performance are menu labels for the existing Best Slips, Slip Builder and Results & performance pages; routes remain unchanged. Builder uses a wrench icon, while Slips keeps its document icon. Community uses the shared group-of-people icon and follows its visibility setting. Items that do not fit move into More. More dismisses on outside touch/click, focus leaving, Escape, destination selection and navigation changes. The information footer follows Contact, Help, Privacy, Terms.

Contextual Back controls and browser history return to the originating screen. Checkout restores safe choices and steps where possible. Unsent payment evidence stays in memory and may need to be reattached after refresh.

## Payment integration and approvals

MTN MoMo/Airtel Money transfers are paid manually in UGX. Authorised administrators set each provider's enabled status, receiving number and registered name. Checkout uses those stored details for manual transfers without provider API credentials.

1. **Choose and pay.** **Package → Pay → Payment Details → Review** starts with selectable packages showing duration, total price, and **Continue to Pay**. All packages include full access; Daily shows **24 hours**. Package, Pay, and Payment Details omit trial notices. Pay shows MTN MoMo/Airtel choices, a compact package summary, and the transfer amount beside the receiving number. Provider changes update values in place while the server quote is revalidated. A valid draft takes precedence over the latest approved, unreversed Mobile Money subscription; otherwise an available MTN, then Airtel, is selected. Wallet credit is optional and can cover part or all of the price. Zero wallet/earned-day balances stay hidden. **Redeem earned days** opens a separate redemption review; earned days extend access rather than discount the cash price. Wallet-only purchases and redemptions require final confirmation.
2. **Submit evidence:** Payment Details offers **Take photo**, **Choose image**, and **Paste image**, with a button-height thumbnail and full preview. Desktop browsers support camera capture with permission and a file fallback; mobile uses device capture. Android camera routing is implemented but awaits native build/device verification and an updated host release; the Windows host retains its camera-denial policy and file fallback. Local OCR reads before upload compression and tries bounded enhancement passes for unclear photos. Editable **Text from image**, an overall reading score, and expandable ID/amount confidence help members correct uncertain results while preserving manual entries and independent messages. Partial or empty readings remain attached for manual correction and explicit review; final valid payment fields remain required. Raw OCR and confidence stay separate from edits, describe recognition rather than guaranteed accuracy, and cannot establish payment verification. Image-derived text cannot count as independent message evidence or survive image removal. Transaction ID and Amount paid retain the desktop 2:1 row and stack on phones; external requests remain pending. Source implementation is complete; deployment remains separate.
3. **Verify and approve:** **Admin → Payments** opens to requests awaiting approval, oldest first. Status and provider filters apply across the queue, and Sort by reorders the current page. Compact numbered pagination stays visible on phones while the two-line payment list scrolls. Desktop updates the selected payment in place. Mobile review shows a compact account summary, and Back to payments restores the queue position. Payment decisions stay in a footer below the desktop review pane or above mobile navigation. Reconciliation, dispute, evidence, reversal, and recovery actions are available from that footer when applicable. **Approve and next** advances to another matching pending request, including across pages. Approval records receipt verification and attempts checkout allocation together, with verified shortfalls kept part-paid. Rejection requires a reason, and reversal requires checked reasons and confirmation, with an optional note. The pending view reloads when idle after a count change.
4. **Activate access.** Approval allocates receipts once, spends reserved balances, credits eligible excess, and grants or extends subscription time atomically. A first paid grant forfeits an unused trial. During an active trial, the full paid period is queued after the trial. Renewals preserve existing time, and top-ups credit the wallet without granting access.
5. **Handle exceptions:** corrections, rejection with a reason, ownership disputes, and shortfalls have workflows. Legacy payments support reversal; current checkout uses reconciliation and ownership resolution. Members track/correct reports. Duplicate-receipt checks, reviewer conflict checks, private evidence, and append-only audit history protect decisions.

See [payment checkout and reconciliation](next-js/docs/payment-checkout.md) for detailed rules and deployment requirements.

## Access and everyday use

Visitors can browse fixtures, scores, slip summaries, completed match predictions, and released slip results. Upcoming/live predictions, detailed insights, slip generation, and restricted controls require server-verified entitlement. Access expires automatically; closing subscription sales preserves existing access checks. Verified administrators have dashboard access and can use subscriber features without a subscription.

Completed public slips can use the sharing drawer without a subscription; unfinished selections remain protected. Exports preserve original picks, odds, and captured outcomes. Their **Average probability** is the mean of selection forecasts, not the probability that the entire slip wins. Images can be forwarded independently of website access.

A typical journey is **browse → inspect a match → register and verify → obtain access → build/share slips → check results**.

## How the app works

- **Shared application:** `next-js/` owns screens, APIs, authorization, and business rules: Next.js/React, TypeScript, shared styled-components themes, Redux, and Prisma with MySQL/MariaDB support.
- **Football processing:** private workers import API-Football data, prepare seven-day prediction runs using East Africa dates, refresh live data, publish revisions/slips, and settle results. Browsing reads stored data. Coverage depends on provider access/evidence.
- **Prediction integrity:** forecasts lock five minutes before scheduled kickoff. Settlement uses verified regulation scores, including stoppage time, excluding extra time/shootouts. Postponements, cancellations, voids, and score corrections preserve audited history. Live scores do not settle predictions.
- **Native and offline:** Flutter supplies persistent sessions, themed recovery, Android pull-to-refresh, external/app links, and sharing. Reconnection and safe cache updates retain the last usable bundle. Prepared anonymous fixture facts/scores remain available for up to 24 hours with staleness notices; predictions, accounts, payments, and writes require connectivity.
- **Operations:** synthetic football/analytics demo data with login identity only; startup does not fabricate subscriptions, payments or wallet credit. A scoped development reset removes known demo offers and their test records while retaining accounts and correcting synthetic credit through the ledger. Automated tests, deployment/package scripts, quota/cost controls, durable job recovery, backup/restore, and monitoring foundations. The dump-safe SharedSlip immutability migration is applied to the configured local MySQL target; hosted deployment is separate. Production scheduling and services need configuration and approval.
- **Local prediction intelligence:** a disabled-by-default shadow engine fits regularized Poisson goals from verified league history, preserves provider forecasts and factual AI context separately, and evaluates chronological ensemble/calibration diagnostics. Semantic checks retain immutable shadow revisions without duplicating unchanged forecasts; a separate durable job can be explicitly registered. Private slip selection requires calibrated marginals and verified dependence evidence, with exposure limits across all six odds bands. Offline reports and synthetic demonstrations grant no publication authority; current public predictions, sorting and UI remain unchanged. See [local intelligence and rollback](next-js/docs/prediction-intelligence.md).
- **Local accuracy evaluation:** free public archive preparation retains a fixed historical data version, original fixture schedules, later result labels and a source-bound verifier. Matched comparisons separate raw model coverage from shadow eligibility. The first small real LaLiga pilot produced mixed results and does not qualify activation; raw data and generated bundles remain local. See [results and limitations](next-js/docs/reports/local-accuracy-285.md).
- **Loading and refresh:** independent reads run together, settlement history uses bounded batch reads, and match details reuse verified projections within their transaction. Checkout, slip and analytics refreshes retain unchanged data and rendered content; overlapping checkout polls share one read. Shared search controls avoid repeated option scans and popup-wide positioning invalidation. Rapid navigation briefly reuses confirmed header state; page/API authorization and explicit session refresh remain server-verified. Offline validation uses bounded parallel reads while retaining every integrity check. Development uses the pinned Next.js default compiler with an explicit Webpack fallback. See the [initial performance audit](next-js/docs/reports/ui-performance-287.md) and [runtime review](next-js/docs/reports/runtime-performance-297.md) for local evidence and remaining limits; hosted response times and physical-device responsiveness remain separate.

## Current boundaries and unfinished work

- **Rollout requirements:** all source migrations are applied to the configured local MySQL target, with application permissions verified and schema/health checks passing. The active owned demo also has all source migrations, while retaining older sharing-schema differences. Hosted/native deployment and coordinated web/worker releases remain separate. See [local migration verification](next-js/dev-plan/296-all-pending-local-migrations.md).
- **Plan deletion rollout:** permanent deletion requires the additional `SubscriptionPlan` DELETE grant on restricted application targets. The owned development demo was cleaned on 5 November 2026, retaining six standard packages, all accounts and the unrelated trial. Source deployment does not reset other databases.
- **Conditional features:** live odds, AI/research, joint-slip estimates, and accuracy claims require permissions, credentials, evidence, and qualification. Demo output establishes no live availability or prediction quality.
- **Shadow-engine limits:** additive `20261105100000_intelligence_shadow` storage is local/test scope only. Historical league identity and original provider receipts must be independently verified; missing evidence causes exclusion or abstention. No paid contextual service, automatic live shadow schedule or production activation is configured by this change. Real historical/prospective accuracy, calibration, whole-slip independence and AI incremental value remain unqualified. Display changes needed for eventual joint-probability activation require owner review under the UI freeze.
- **Partial foundations:** expanded goal/bookmaker-implied markets have derivation/storage/settlement groundwork; public activation is unfinished. Owner cost accounting lacks a complete profit service/interface. Some legal/publication and unattended-operation checks remain open.
- **Platform gaps:** Android/Windows have recorded local execution evidence; Apple requires host/device qualification, and Linux lacks a qualified browser. Signing, domain app links, stores, hosting, and full release acceptance remain separate work.
- **Alert qualification:** real Web Push/FCM delivery, device lifecycle/sound and operational timings need credentials, rebuilds and acceptance. Windows closed-process WNS needs identity/packaging approval; no background daemon was added. See [alert setup, verification and rollback](next-js/docs/payment-review-alerts.md).
- **Scope limits:** additional languages, advertising, exact-score public forecasts, and match/result alerts are not delivered. Predictions are estimates, never guarantees.

# Extended market persistence

Phase 053 and Phase 054 extend an existing canonical `PredictionSet`; they do not replace its four legacy `MarketPrediction` rows or change `candidateJson`. One immutable `GoalMarketExtension` and one immutable `ImpliedMarketExtension` can each reference that exact revision, cycle and fixture. The goal extension records the validated joint score distribution and deterministic derivations from a reviewed, period-qualified catalogue. An absent extension means there is no extended forecast for that historical revision.

The publication service writes an optional extension immediately after appending the canonical revision and before moving the current-cycle pointer, within the same fixture transaction. The goal repository cannot begin a transaction or change a current/locked reference. It refuses retrofitting an already accepted/current legacy revision, while a repeat of an existing identical extension returns the original archive. Full model-output provenance and reviewed definitions require the publication authority's separate extension proof; matching the old marginal groups alone is insufficient.

`ExtendedMarketSettlement` is a current pointer keyed by cycle and canonical market key. `ExtendedMarketSettlementRevision` preserves the exact prediction revision, selected pick, source, verified result, previous revision, reason and correction time. It distinguishes Correct, Incorrect, Half win, Half loss, Push, Pending, Void and Unavailable. Both sources reuse the existing `SettlementBatch`, fixture version and durable invalidation event. Goal settlements revalidate a planned write against sealed source rows in the same transaction; a caller-created object cannot replace a locked pick.

The optional `extendedMarketsEnabled` settlement capability defaults to false. Existing workers therefore never access newly introduced tables until migrations and appropriate runtime grants have been reviewed and installed. Enable it only for a deployment that has the additive migration, source-specific catalogue and publication authority in place. Extended results have a separate keyed read/audit projection and are excluded from the legacy four-family headline metrics.

Separately verified period scores are required for half-time, second-half and HT/FT outcomes. These markets stay Pending when that evidence is absent, even if a raw provider payload happens to contain a halftime pair. `ImpliedMarketResultEvidence` provides a separate immutable result-time fact stream for statistical/event markets, bound to the exact canonical fixture-result revision; prediction-time averages are not settlement evidence. Missing distribution mass, missing joint half-time support and incomplete provider groups remain explicitly unavailable rather than acquiring invented probabilities.

The migration creates six additive InnoDB tables with binary identities, composite foreign keys and payload integrity checks. `ExtendedMarketPublishedPick` stores bounded immutable pick projections so feed reads need not load score distributions or complete provider catalogues. Database triggers prohibit UPDATE and DELETE on both extension archives, result-time evidence, published picks and settlement revisions, even if the runtime role is accidentally granted broad mutation privileges. Runtime grants should still be limited to SELECT/INSERT on these archives and SELECT/INSERT/UPDATE(revisionId) on the pointer table. A rollback disables the capability and publication extensions, retaining all archive tables and history; it does not delete forecast evidence.

Extended performance groups source, canonical market key and rule version separately. It uses current settlement pointers for the applicable cycle and excludes stale terminal outcomes after result or statistical-evidence corrections until reconciliation replaces those pointers. Half wins, half losses and pushes keep explicit counts and do not enter the binary hit-rate denominator. Descriptive outcomes do not establish probability calibration for either model scores or bookmaker prices.

Focused contract tests cover deterministic derivation, bounds, sealed round trips, missing evidence, lock binding, distinct payout grades and historical void evidence. The integration suite uses only an owned disposable genuine MySQL instance and synthetic provider/model data; it exercises real publication rollback/idempotence, additive migration drift, default capability isolation, quarter payouts, corrections and forged-plan rejection. Production migrations, grants and provider calls are not part of these tests. The phase acceptance rows remain incomplete until the complete provider catalogue, verified period/result pipeline, public projections, activation and all required acceptance checks are complete.

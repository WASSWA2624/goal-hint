## Changes made during this audit

- Saved-slip history now recognises canceled, abandoned and awarded forecasts as void under the existing market rules. It retains original selections and quoted odds, exposes no active/postponed legs, and does not count a slip with a void leg as a win. The UI distinguishes forecast outcomes and original quotes from bookmaker payout decisions.
- Saved-slip grading now batch-loads sealed result snapshots and verifies their canonical status, regulation score/evidence and lifecycle coherence before using them. Stale or conflicted scores remain pending instead of producing a false win/loss.
- Focused tests cover mixed won/lost/void/pending legs, active-leg privacy, stale canonical corrections, lifecycle conflicts and failed result integrity. MySQL integration coverage was expanded for the same cases.

Saved-slip history still follows current fixture status. If a terminal fixture is later restored to scheduled/live, the original saved slip becomes private again; it cannot be tied safely to the old void cycle without stored cycle/revision identifiers. A legacy postponed fixture is therefore not automatically published as void. Fix this with a versioned cycle-bound snapshot/publication archive rather than guessing a historical cycle from kickoff dates.

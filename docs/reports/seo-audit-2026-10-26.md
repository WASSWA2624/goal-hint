## Method

Seven read-only auditors (content and links, indexing, redirects and canonicals,
sitemaps, metadata and languages, structured data and trust, mobile performance)
inspected the code and a local dev server on the populated local MySQL. A skeptic
re-ran every finding against the code, the server and current Google/Next.js
documentation, and a completeness critic looked for gaps. 41 findings survived;
they reduce to the items below. Five file-disjoint groups were implemented in
separate worktrees, each reviewed adversarially and fixed, then merged.

## Not changed: owner decisions and blockers

- **Hosting suspension** (above). Everything else is secondary until it is lifted.
- **`/en/performance` stays noindex.** It is the public track record, but it shows
  win/loss counts, losing streaks and illustrative returns while OP-17 (public
  performance claims) is unresolved. Enabling it is a one-line `index` change plus
  a sitemap entry; recorded in `docs/seo-discovery.md`.
- **Provider-only analysis.** Production forecasts are API-Football only, so every
  indexable match page carries the same template "Why we think so" text, repeated
  under News & Insights as "Goal Hint analysis". Whether to index provider-only
  forecasts, and how to label that text, is the owner's call. Anonymous visitors
  and Googlebot do not see it (paywalled).
- **Help page trust content** (who runs the site, responsible-gambling guidance,
  a link to the track record) needs owner-approved copy.
- **Anonymous HTML is `no-store`** (documented paywall decision), which blocks the
  back/forward cache.
- **Contact address**: the published `wasswawilon0002@gmail.com` differs by one
  letter from the git author address; please confirm it before adding it to
  structured data.
- **Deferred performance work** (measured, not changed because it overlaps the
  owner's uncommitted feed/card edits): the access bar is inserted after
  hydration (likely layout shift; needs a browser measurement), `/en/matches`
  embeds the 428-league filter catalog in its RSC payload, and feed routes load
  zod eagerly.
- **Pre-existing verifier drift** (not caused here): `verify-production-paywall.py`
  rejects the public-chance `probabilities` key added by `b2b3d8d`;
  `verify-navigation-rendering.py` predates the Results & performance nav item
  and the header account changes; `tests/match-detail.integration.mjs:299` gets
  503 from the detail API on the base commit too.

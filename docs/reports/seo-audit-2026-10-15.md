| SEO failure | Blocked from indexing; nine other audits passed | Both robots meta and the HTTP header were reported. |

The dominant first-party chunk accounts for 2,168 ms of script evaluation.
The report also shows `/en?tz=America%2FLos_Angeles`. Source inspection confirms
that `FeedSurfaceContent` immediately calls `router.replace` to adopt the device
timezone, while `feedDiscovery` deliberately marks timezone variants noindex.
The local live browser likewise moved to `/en?tz=Africa%2FKampala`.

Therefore, opening the release gate alone does not resolve the rendered-homepage
problem: automatic timezone navigation can still take a browser/crawler to a
noindex variant. This is also a candidate for avoidable startup work; the report
does not isolate its individual CPU cost. A follow-up should keep the canonical
landing URL stable, preserve device-local dates through an explicit control or a
client data update, and test near midnight in multiple timezones. Do not simply
make all filtered URLs indexable to improve a score.

For the performance target, profile the main chunk, reduce the client-rendered
surface, load optional filter/calendar panels on demand, and remove repeated
startup renders while preserving server HTML and working controls. Measure LCP
and blocking time over several comparable mobile runs. LCP below 2.5 s and low
blocking time are useful milestones, but neither guarantees a score of 100.
There is no CrUX field data in the supplied report. This branch makes no measured
performance-score improvement claim.

## Implemented changes and before/after evidence

| Change | Before | Local result |
| --- | --- | --- |
| Root redirects | Root-page redirect dropped query parameters; HTTPS www root needed two hops. | Configuration redirects retain filters, repeated parameters and pagination, and send www root directly to the canonical `/en`. |
| Sitemap scope | Advertised nested shards depended on explicit submission for URLs outside their directory scope. | Index advertises `/sitemap-matches-N.xml` and `/sitemap-archive-N.xml`; root rewrites reuse native handlers. The directory-scope regression failed before the change and passes afterward. Native URLs remain available. |
| Forecast previews | Voided forecasts looked like ordinary estimates; open/partial forecasts were described as a locked record with all markets. | Verified void status is disclosed at the start of search/social descriptions. General descriptions say available markets and forecast history. Identity-mismatched outcomes cannot supply a void label. |
| Visible record context | Main pick omitted source, provisional status and delayed-result warning. | A compact shared-style note shows exact-snapshot provenance, applicability and relevant stored warnings in initial HTML, including on mobile. Historical records do not borrow current forecast provenance. |
| Narrow-screen match layout | The long-team-name fixture expanded the verdict grid beyond a 320 px viewport. | The verdict now uses a shrinkable `minmax(0, 1fr)` grid track so its contents can wrap inside the available width. |
| Acceptance coverage | Render harness expected old campaign redirects without consent attribution fragments. | Expectations preserve the established fragment behavior while asserting clean functional queries, redirects, root sitemap aliases and prediction record text. |

The deployment release gate, provider access, production database, evaluation
policy and forecast records are unchanged. Reverting the branch's code changes
restores previous application behavior; no data migration is required.

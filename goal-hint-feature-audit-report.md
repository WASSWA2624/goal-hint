## Key risks

- **Highest delivery risk:** subscriber configuration and referral persistence are absent at every layer. A dropdown or dashboard mock alone cannot satisfy these requirements.
- **Authentication policy mismatch:** a second login currently invalidates the first. Existing passing tests deliberately enforce this behavior. Do not confuse paid-device unlocking with authenticated-session concurrency.
- **Reward accounting risk:** referral rewards must be awarded exactly once at verified registration, without a payment condition or lifetime cap. Existing UGX credit and registration trials cannot stand in for earned days. The auto-renewal path can buy access before expiry, so reward consumption must have explicit priority to avoid indefinitely postponing earned access or spending credit unexpectedly.
- **Sharing contract mismatch:** the drawer and older sharing documentation promise universal link visibility, while the current service withholds active selections from non-entitled recipients. Preserve access controls and align the landing/copy. Distributed PNGs already contain the explicitly shared selections and cannot be revoked by a later subscription change.
- **Verification limits:** unit tests do not establish deployed migrations, database privileges, messaging coverage, proxy trust, scheduling, provider accuracy or signed-device behavior. Development demo seeding can write data on reads; live viewer reads can auto-renew access. No live application/database requests were made during this audit.
- **Performance interpretation:** production counts are available in code, but approved quality metrics and probability-band analysis are deliberately gated. Synthetic demo values and fixed-unit aggregate returns must not be presented as verified production performance or personal betting results.

## Dependencies and unanswered questions

- **Configurations:** use the authenticated member/account boundary, existing criteria validation, database migration/application grants and shared UI controls. Decide whether saved dates are absolute or rolling relative to today, whether loading a default happens on each builder visit, and whether configurations remain manageable after a subscription expires. Loading must never generate slips automatically.
- **Referral identity/security:** define attribution expiry and first/last eligible link rules, treatment of existing/unverified accounts, phone changes/account merges/erasure, and narrowly scoped fraud review/reversal. Confirm how “one verified new registration” is identified after number changes. Keep valid reward accumulation uncapped.
- **Access ordering:** decide how queued paid periods, earned days and optional credit auto-renew interact, including a paid purchase while earned access is running. Preserve unused valid rewards and apply them after paid access ends.
- **Sessions:** confirm whether phone-number authentication means phone + password on an already verified account, or a fresh OTP on each new login/device. Decide whether administrators share the member two-session policy; current code gives administrators the same one-session replacement behavior.
- **Notifications and sharing:** define “relevant match results” and essential account events; decide whether active shared links should lead to gated sign-in or explicitly public selections, and whether individual-prediction image sharing is required. Validate real release signing/association configuration without exposing private credentials.
- **Match/performance data:** confirm provider coverage/reuse rights for additional player data, the authorized evaluation-policy binding, expected market coverage and reporting windows. Verify deployed schema/grants and worker health in a suitable environment before declaring runtime completeness.

## Recommended implementation order

Each step is a recommendation requiring its own explicit approval; none was implemented.

1. **Saved configurations and account entry:** implement the per-user store/API, ten-item/default rules and complete builder lifecycle; expose management on the existing subscriber account page. Verify persistence across sign-out and devices, ownership, and load-without-generation.
2. **Complete the account summary and session policy:** show the current package, expiry/time remaining and existing payment activity; implement the two-session invariant with server revocation and concurrency checks before relying on cross-device access.
3. **Referral eligibility, fraud controls and day accounting:** establish secure attribution and exactly-once verification rewards; integrate earned access with paid expiry/renewal before displaying a reward balance as spendable.
4. **Subscriber referral summary and Invite Friends:** add the personal link, referral statistics, earned/used/remaining days and quiet invitation entry points using the approved ledger.
5. **In-app account/access notifications:** add essential subscription, renewal, expiry and reward events, then relevant prediction/result events. Reuse existing inline notices; add no external reminder channels.
6. **Targeted sharing/mobile completion:** reuse the current share pipeline on phones, resolve restricted-recipient messaging and test native/manual handoff. Validate the complete builder/account/referral journeys at phone sizes.
7. **Data qualification and performance completion:** verify representative provider/result histories, complete any necessary player-data gaps, and bind approved performance reporting. Keep the existing detail/performance screens and avoid personal betting tracking.

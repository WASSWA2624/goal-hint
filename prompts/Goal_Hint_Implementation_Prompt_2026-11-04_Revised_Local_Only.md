# Goal Hint — Prediction Intelligence and Production Improvement
**Implementation prompt for coding agent | 4 November 2026**

## Objective and constraints
Improve Goal Hint's football-only prediction accuracy, whole-slip reliability, speed, cost efficiency and production readiness. Support men's and women's football wherever provider coverage and data quality permit. **Quality over quantity:** publish no slip when no combination qualifies. Predictions are estimates, never guaranteed wins or profits.

Produce a gap matrix with source evidence, risks, acceptance criteria and affected files. Extend existing functionality rather than rebuilding it. STRICT UI FREEZE: Do not modify any user-facing UI, layout, styling, navigation, labels, interactions, or frontend components. If a backend change requires a UI change, document the blocker and request owner approval rather than changing the UI; preserve accounts, subscriptions, manual payment verification, referrals, community links, saved filters, branded sharing, canonical links, access control and settlement history. ## 1. Three prediction components and one validator
**Provider:** Store API-Football's available forecast, supported markets, quoted odds, source and observation time. Never invent provider probabilities where absent.

**Local statistical engine:** Independently estimate outcome probabilities from football facts, not copied provider predictions. Implement a reproducible, regularised Poisson/Dixon–Coles-style goals baseline, team attack/defence and home advantage; evaluate Elo or additional machine learning only if tested improvement justifies complexity. Consider recent form, opponent strength, league, home/away, transfers, squad changes, manager/tactical changes, injuries, suspensions, rest, expected line-ups, player roles and red-card circumstances when point-in-time evidence exists. Weight recent data appropriately, widen uncertainty for sparse data, and never invent missing player/event effects. Generate internally coherent probabilities for existing match-result, double-chance, over/under 2.5 and both-teams-to-score markets.

**AI contextual layer:** Use only authorised, timestamped news/research sources when configured. Evaluate injuries, expected versus confirmed line-ups, weather, pitch, travel, security disruptions, tactical and managerial news. Distinguish verified fact, credible report, rumour and unknown; cite evidence. First assess underlying facts without other models' conclusions where feasible, then compare with provider/local forecasts. AI must not manufacture facts or supply unvalidated numerical probabilities. Reserve paid AI for cases likely to benefit.

**Final validator:** Keep all component outputs separate. Learn calibrated ensemble weights from historical out-of-sample performance by market/league when sample size supports it; shrink to a robust global baseline otherwise. Account for correlated inputs; agreement alone is not proof. Separate **calibrated winning probability**, **evidence reliability**, **model uncertainty** and **odds value**. Material disagreement prompts scrutiny or abstention, not blind averaging. Return outcome, probability, uncertainty/evidence grade, model versions, provenance, explanation and publish/withhold decision. Reject stale, unsupported or low-quality recommendations.

## 2. Collection, monitoring and reassessment
Retain the existing seven-day EAT-oriented background-worker pipeline. Perform one comprehensive daily baseline run. Start with configurable hourly lightweight checks for relevant near-term fixtures, less frequently for distant fixtures, prioritising matches on published Best Slips. Confirm API-Football endpoint access, batching, quotas and caching terms before choosing exact schedules: hourly checking is not necessarily one request.

Compare normalised new observations against stored observations by field/hash. Classify **critical** changes (postponement, cancellation, confirmed major absence, unexpected lineup, serious security issue), **significant** changes (credible tactical/manager news, substantial odds shift, travel/weather or a local probability shift of initially five percentage points), and **minor** changes (duplicates or immaterial movement). Five points is a *review trigger*, not an established optimal threshold; validate it. Recompute locally first; call AI only if contextual interpretation is justified. Suspend invalid fixtures. Missing updates do not imply unchanged facts. Use deduplicated, idempotent jobs, rate limits, backoff, circuit breakers, durable retries and strict provider/AI daily and monthly budgets. On quota exhaustion or outages, degrade safely or abstain; never silently overspend.

Preserve the existing five-minute-before-kickoff forecast lock. Significant updates may change future recommendation eligibility and flag affected published slips, but must never overwrite original published predictions, selections, odds or history.

## 3. Efficient persistence
Extend existing Prisma/MySQL tables only after schema inspection. Store: source observations and timestamps; separate provider/local/AI outputs; final calibrated forecast and model version; evidence and revision reasons; latest-approved pointer; immutable published picks/slips; settlement; evaluation results; compact monitoring and API-cost aggregates. **A check is not a new prediction version.** Create versions for meaningful evidence/model/publication changes, and retain all forecasts actually published or needed for reproducible evaluation. Deduplicate unchanged payloads and news, index fixture/market/source/version/time, enforce unique job and publication keys, use transactions, and establish retention/archival for operational logs without deleting required audit evidence. Test backup and restore.

## 4. Slip selection and user features
Keep all six existing total-odds bands with current boundary rules: 2.50–5.00, 5.00–10.00, 10.00–20.00, 20.00–50.00, 50.00–100.00, 100.00–200.00. Preserve the Slip Builder's match and slip odds ranges, probabilities, markets, date/time, match count, slip count, match reuse, saved presets and sharing.

Use only validated eligible selections. Estimate **whole-slip joint win probability**: multiply only where independence is defensible; account for shared fixtures, related markets and correlations, otherwise conservatively exclude uncertain combinations. Do not label average match probability as whole-slip probability. Rank qualifying slips within bands by defensible joint probability and evidence quality, with odds and diversity constraints. Limit repeated exposure to the same match across published slips. Leave bands empty when none qualifies; never manufacture candidates. Keep original published slip references and outcomes immutable. Ensure displayed sorting labels match actual sorting logic.

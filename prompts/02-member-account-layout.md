# Implement the member Account workspace layout

Apply the layout and visual conventions of the administrator’s Overview, Payments, and Subscribers screens to the signed-in member Account pages. Use the supplied screenshots as interface references. Keep this change focused on the Account layout and the shared components it needs. Obtain approval before undertaking a major additional redesign of an established interface.

## Current source and starting points

- `next-js/src/components/members/account-workspace.tsx` already renders a desktop Account sidebar, a narrow-screen section disclosure, and an adjacent content area. It shares `WorkspaceNavigationLink` with admin and uses desk primitives such as `DeskHead`, `Panel`, and `StatGrid`.
- `next-js/src/app/_components/account-route.tsx` resolves the current section, member session, safe return destination, and section-specific data. It renders the page heading. `next-js/src/components/members/account-panels.tsx` supplies a second Subscription heading through the summary panel used on both Overview and Subscription. Review both call sites when correcting the heading hierarchy.
- `next-js/src/domain/account-navigation.ts` owns section parsing and hrefs for the localized Account route. It preserves the safe `return` query when building section links. Review existing notification and referral cursor navigation and any links or forms that leave and re-enter Account.
- Inspect `next-js/src/components/ui/workspace-navigation.tsx`, `next-js/src/components/admin/admin-workspace.tsx`, and `next-js/src/components/admin/desk-styles.tsx` for shared navigation, headers, layout, panels, rows, toolbars, and sticky actions. Inspect `next-js/src/components/admin/record-workspace.tsx`, `payments-editor.tsx`, and `subscriber-workspace.tsx` in the same directory for pane geometry, list/detail navigation, and action footers. The current record-view history helper applies its mobile history behavior to `/admin/` paths. Check its assumptions before sharing that behavior with the localized member route.

## Layout and behavior

- On wide screens, keep the Account section navigation consistently on the left. For a section with a meaningful list of records or subsections, place its nested list or menu beside the section navigation and render the selected content in the adjacent main pane. Reuse the admin workspace’s alignment, compact rows, selected states, pane headers, and spacing where appropriate. Keep Overview and simple content or forms in a single content pane when they have no useful list to drive selection.
- Use the existing data and actions to decide where a nested list, search, filters, an Advanced filters entry, or a primary toolbar action helps members. Review existing record-bearing sections such as Payments, Notifications, and referral reviews against that criterion. The references establish the pattern and leave the section-by-section placement open. Pick placements supported by the actual data and workflow. Keep available result scope and pagination accurate if you add search or filters.
- Put an existing action for a selected record or detail view in its detail pane footer when appropriate. Keep section-wide actions in their appropriate section or list controls. Preserve action availability, confirmation and feedback, including in pending, unavailable, and empty states.
- On narrow screens, retain the current responsive Account section navigation, its selected state, and its keyboard and dismissal behavior. Use the established mobile list-to-detail flow where a list exists. Returning from details should restore the prior list context, including selection, scroll, and focus where applicable. Keep detail footers visible and usable above the mobile app navigation, including on short screens.
- Use one clear page heading. On Subscription, show the title once and keep the summary status and facts readable. On Overview, keep Subscription as a meaningful subsection heading. Preserve accessible names, heading order, landmarks, focus visibility, and keyboard navigation in both layouts.
- Preserve section URLs, current section and safe return behavior, browser back and forward navigation, localization, session and role checks, and member-only data access. Preserve existing subscription, wallet, payment, referral, security, device, notification, and activity workflows. Reuse or extract presentation primitives where they serve both workspaces. Keep member authorization and data loading in the member route and services.

## Repository standards and acceptance checks

- Keep the web implementation in `next-js/`. Use shared theme tokens, `theme.radius`, control heights, and row layouts. Review `next-js/docs/corner-radius.md` and `next-js/docs/control-uniformity.md`. Keep the app header, navigation, and stable workspace chrome mounted as sections and record values change. Use shared `NavigationProgress` immediately below the app header for foreground loading and `aria-busy` on pending content, or `AppLoading` when there is no content container. Keep existing content and control labels visible when possible and leave passive refresh quiet.
- Check Overview, Subscription, a populated list/detail section, and a simple security form on desktop and mobile in both light and dark themes. Verify the title hierarchy, toolbar and footer placement, keyboard operation, focus restoration, and reachability above mobile navigation. Exercise long labels and both empty and loaded sections.
- Open a localized section deep link with an allowed return destination. Navigate across sections, open and close a record on mobile, use browser Back and Forward, and follow the return destination. Verify existing cursor navigation and member-owned record access. Check signed-out, blocked, and admin redirect behavior. Run the existing Account navigation and relevant member route or rendering checks, and regression-check any admin screens that now share changed primitives.
- Update `APP_OVERVIEW.md` in the implementation change to describe the member workspace and its behavior. Distinguish source changes from deployment status.

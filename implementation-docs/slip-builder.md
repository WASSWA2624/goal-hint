# Slip Builder

## Purpose and scope

**Builder** at `/en/slips` assembles transient slips from selected criteria, stored forecasts and eligible bookmaker offers. A fixture used in one build remains available to other builds and automatic publications. **Slips** at `/en/best-slips` browses the published archive. [Builder route](../next-js/src/app/_components/slips-route.tsx), [automatic slips](automatic-slips.md), [shared interface](ui-implementation.md).

## Inputs and validation

The settings panel shows the applied criteria. A softly shaded heading introduces the summary. Each tile aligns its thin-stroke icon with the stacked label and medium-weight value. Labels and values each use one line. Desktop uses a compact four-column grid with **Filters** and **Build slips** stacked to the right of a divider. On compact screens, the heading includes a subtitle, and the tiles are followed by full-width rows for match reuse, the date and time window, and Markets. Narrow phones rearrange the tiles and place the date and time value below its label. The actions sit side by side below the summary. **Build slips** uses a blue tint, and **Filters** uses the neutral section color. The Markets value ends with a `+` when shortened. Assistive technology receives the full value. [Criteria summary](../next-js/src/components/slips/slip-criteria-summary.tsx), [panel styles](../next-js/src/components/slips/slip-builder-settings-styles.ts).

**Filters** opens a draft with slip targets, individual odds and probability limits, the kickoff window, reuse and Markets. **Apply Filters** validates the draft and updates the criteria summary for the next build. Ordinary edits can leave the previous generated slips visible. Reset stages the standard defaults and clears the selected preset. Applying that reset or a changed preset also clears the previous display. Cancel or Escape restores the values from before the dialog opened. Backdrop clicks leave the dialog open. [Builder controls](../next-js/src/components/slips/slip-builder.tsx), [shared dialog](../next-js/src/components/ui/criteria-dialog.tsx).

**Markets** opens a searchable child dialog. A checked family uses **Automatic** until the user specifies outcomes. Deselecting a family or restoring Automatic clears its explicit outcomes. Match total lines pair Over and Under, and team totals group those pairs by home and away. Searches keep chosen values when options are hidden. Markets Apply stages the choices in the parent draft. Markets Reset restores the four default families with Automatic outcomes. [Market picker](../next-js/src/components/slips/slip-market-filter-fields.tsx), [market dialog](../next-js/src/components/ui/market-filter-dialog.tsx).

Enhanced numeric controls preserve typing, deletion and pasted drafts and report format, range and ordering errors. Apply, Build and preset writes validate canonical values. Before JavaScript attaches, the same GET form provides inline criteria and market checkboxes. A legacy/default form uses separate native date and time inputs in this view. Explicit date-time URLs keep combined endpoints and their zone. Hydration enables the filter dialogs and combined From/To controls. [Criteria fields](../next-js/src/components/slips/slip-criteria-fields.tsx), [numeric guards](../next-js/src/domain/slip-input-guards.ts), [Builder form](../next-js/src/components/slips/slip-builder.tsx).

| Filter | Default and rules |
| --- | --- |
| Kickoff | The Kampala reporting date with a displayed window of 00:00–23:59. Default and legacy `dateFrom`/`dateTo` and `timeFrom`/`timeTo` use Kampala minutes, including recurring daily time bounds on multiday legacy requests. Explicit `start`/`end`/`tz` specifies a continuous interval. The end minute is included and either form spans at most 31 calendar dates. |
| Number of slips | 5 requested, with supplied counts from 1 through 100. A submitted blank count is invalid. The returned count can be smaller. |
| Total odds | 5.00–10.00 by default. An omitted maximum uses 10.00 and an explicitly blank maximum is unbounded. Inclusive bounds compare the exact product, including when the lower and upper bounds are the same. |
| Individual odds | Minimum 1.01 with no default maximum. Odds-filter inputs accept up to two decimal places. Quotes can retain up to four, and displayed totals round half-up after comparison. |
| Individual prediction probability | 75%–100% by default. The input accepts 0%–100% to three decimal places with inclusive bounds. The stored Builder applies an effective 75% floor, so a maximum below 75% yields no qualifying slips. |
| Whole-slip probability | The ordinary form leaves it unrestricted. Restrictive `totalProbMin` or `totalProbMax` requires a qualified joint model. The controls appear with an approved model or when a URL supplies those fields. |
| Matches per slip | One minimum with an unrestricted maximum by default. Supplied counts are whole numbers and any maximum must be at least the minimum. Available distinct fixtures and search bounds limit the build. |
| Reuse Matches | Off by default. Every slip contains distinct fixtures. Off also prevents reuse across the returned set. On allows a fixture to appear in multiple different slips. |
| Markets | The four base markets are selected by default with automatic outcome choice per family. Team goals is opt-in. Selected outcome lists restrict the permitted choices for that market. |

The four default families are 1X2, double chance, BTTS and full-time match totals. Match and team totals cover 1.5, 2.5, 3.5, 4.5 and 5.5. Extended selections require a sealed forecast and a usable exact quote for that fixture, period, line and side. Blank odds, match-count and individual probability minima use their defaults. Legacy and explicit time parameters are mutually exclusive. Once mounted, the device-zone hook supplies today's date and zone for older time-only presets. Default form and legacy URL windows continue to use Kampala, and explicit intervals retain the supplied zone. ## Build flow and result handling

1. **Build slips** submits a read-only GET to the Builder page with `build=1`. The enhanced control validates and serializes the form, then navigates to the canonical URL or refreshes the same URL for an identical repeat. A load without `build=1` opens criteria for editing. Malformed requests preserve recoverable inputs and skip the forecast and odds cohort read. During generation, the controls remain visible and pending content is marked busy. [Form and result state](../next-js/src/components/slips/slip-builder.tsx), [route validation](../next-js/src/app/_components/slips-route.tsx), [navigation feedback](ui-implementation.md).
2. Guests and restricted signed-in members can edit criteria. **Unlock slip builder** leads guests to login and restricted members to the subscription journey. Eligible signed-in members have build access with Paid Access Off. With Paid Access On they need an active issued period. Administrators can build in either mode. The route checks access before generation and rechecks it before returning picks. [Viewer access](../next-js/src/server/members/viewer-access.ts), [gated reads](../next-js/src/server/members/gated-reads.ts), [subscriptions](subscriptions.md).
3. With approved odds rights, the service consumes the shared database-backed Matches search allowance and reads up to 500 fixtures in a repeatable-read cohort. The query uses the configured competition scope, an open cycle and a scheduled fixture with a published forecast still before the five-minute publication deadline. It excludes blocking lifecycle evidence and known early starts. Before returning, a selected-fixture check verifies current schedule, cycle and availability. Drift can remove affected slips or make the result unavailable. [Service](../next-js/src/server/slips/slip-service.ts), [cohort](../next-js/src/server/slips/slip-cohort.ts), [search limiter](../next-js/src/server/matches/search-limit.ts), [odds rights](../next-js/src/server/odds/public-odds-policy.ts).
4. The shared combination search considers the selected markets in stored forecasts, including usable published fallback sources. Each leg uses its own verified exact bookmaker quote. A slip can combine prices from different bookmakers, and lower-priced variants can help meet bounded totals. The search prunes impossible products and bounds work at 800 candidate offers, 100,000 search nodes and 100,000 batch nodes. It retains up to 2,000 ranked combinations with a separate aggregate leg budget. [Price reader](../next-js/src/server/slips/price-read.ts), [combination search](../next-js/src/domain/slip-builder.ts).
5. Default ranking uses the conservative lower bound derived from leg probabilities, then exact total odds, fewer legs and stable identity. With reuse Off, the bounded compatible-set search favors a larger disjoint set and higher ranks among ties. The default web binding supplies no joint estimator. Restrictive whole-slip probability bounds yield `model-unavailable` in that binding. [Ranking](../next-js/src/domain/slip-builder.ts), [model binding](../next-js/src/server/slips/joint-model.ts).

## Results and match updates

Generated slips stay in the current page result. The browser sorts the set by average leg probability, preserves build order at equal values and shows 20 cards initially. Show More reveals the next 20 from the generated result without scrolling the page. A new build starts with the first 20. Shared cards key each slip by its generated ID and show its original total odds, average prediction probability, match count and selections. Desktop uses the aligned ledger, and phones use the compact disclosure. Match rows can display current score, phase and outcome beside the original pick and price. Average leg probability describes the picks, while the selection bound serves the search. [Result list](../next-js/src/components/slips/slip-builder.tsx), [pagination](../next-js/src/domain/slip-pagination.ts), [shared slip card](../next-js/src/components/slips/slip-card.tsx), [shared responsive UI](ui-implementation.md).

On desktop and phones, the visible page starts one stored observation loop for distinct original selection identities. `POST /api/slips/match-states` checks access and reads cycle and revision evidence. It updates scores, phase and outcomes about every 20 seconds while available. The loop pauses when hidden, offline or navigating. Transient failures back off and access loss hides the protected cards and asks the server to recheck. Passive updates leave criteria, the result set and original picks, odds and probabilities in place. Submitting a build or reloading its URL recomputes against stored data. [Observation provider](../next-js/src/components/slips/slip-match-refresh.tsx), [polling](../next-js/src/domain/slip-match-polling.ts), [server match states](../next-js/src/server/slips/slip-match-states.ts).

Missing odds, absent qualifying fixtures, qualifying fixtures without a matching combination, joint model unavailability, rate limits and data errors have separate result states. Builder reports a smaller generated count and indicates bounded search or partial cohort coverage when applicable. [Result states](../next-js/src/domain/slip-page.ts), [build service tests](../next-js/tests/slip-service.test.mjs), [search tests](../next-js/tests/slip-builder.test.mjs).

On 26 November 2026, staging accepted valid desktop and mobile submissions and displayed **Odds unavailable**. Its configured profile had neither a public odds rights reference nor the corresponding approval. The service returned before reading fixtures. An isolated fixture with qualifying prices generated two slips on desktop and mobile, and a production diagnostic request also generated results. [Odds policy](../next-js/src/server/odds/public-odds-policy.ts), [Build service](../next-js/src/server/slips/slip-service.ts).

## State, saved filters and sharing

- Eligible signed-in accounts can manage up to ten presets independently of generation entitlement. **Custom Filters** loads a preset into the draft. **Manage Custom Filters** offers **Save as new**, **Update selected**, **Rename**, **Delete** and **Use as default**. Save and Update capture valid criteria with their exact interval and zone. A default applies once on an untouched visit with no query. Explicit URL values and local edits take precedence. Applying a changed preset writes a criteria-only URL and its configuration ID. Reset clears the draft selection and keeps the records. Deleting the applied preset clears its ID and keeps the applied values. [Preset interface](../next-js/src/components/slips/saved-slip-configurations.tsx), [draft and URL behavior](../next-js/src/components/slips/slip-builder.tsx), [preset normalization](../next-js/src/domain/slip-configurations.ts).
- `GET` and `POST /api/account/slip-configurations` read and write account-scoped `SlipConfiguration` rows. The service checks session and account status, normalizes names, enforces uniqueness and uses revisions to reject stale writes. A focus or visibility refresh rereads records while preserving an in-progress edit. [Preset API](../next-js/src/app/api/account/slip-configurations/route.ts), [preset service](../next-js/src/server/slips/slip-configurations.ts), [preset interface](../next-js/src/components/slips/saved-slip-configurations.tsx), [Prisma schema](../next-js/prisma/schema.prisma).
- Builder uses its image export flow for new personal slips. `POST /api/slips/number` can obtain a stable display number from a fingerprint without storing the selections. New canonical share links refer to published Best Slips. Previously issued private/shared snapshot links retain their original read path. [Number endpoint](../next-js/src/server/slips/slip-numbers-http.ts), [Sharing endpoint](../next-js/src/server/slips/shared-slips-http.ts), [Storage migration](../next-js/prisma/migrations/20261103120000_transient_slips_and_odds_bands/migration.sql).

# Slip Builder

## Purpose and scope

**Builder** at `/en/slips` assembles slips from the user's filters and stored forecasts and bookmaker offers. **Slips** at `/en/best-slips` browses independently published recommendations. Builder results can share fixtures with automatic slips and with other Builder requests. [Builder route](../next-js/src/app/_components/slips-route.tsx), [Automatic slips](automatic-slips.md).

## Inputs and validation

The **Filters** dialog edits a draft. **Apply Filters** prepares the settings for the next build. **Build slips** sends a GET to the same page with `build=1`, including canonical criteria. Malformed inputs remain editable and avoid a prediction/odds cohort read. [Builder component](../next-js/src/components/slips/slip-builder.tsx), [Criteria parser](../next-js/src/domain/slip-builder.ts).

| Filter | Default and rules |
| --- | --- |
| Kickoff | Today's reporting date with the whole day offered in the form. Explicit From/To entries use local minutes and an explicit time zone. The end minute is included and the range spans at most 31 calendar dates. Legacy date/time URLs use Kampala time. |
| Number of slips | 5 requested, with integer inputs from 1 through 100. Results can fall short. |
| Total odds | 5.00–10.00 by default. An explicitly blank maximum is unbounded. Inclusive bounds compare the exact product, including when the lower and upper bounds are the same. |
| Individual odds | Minimum 1.01 with no default maximum. Odds-filter inputs accept up to two decimal places. Quotes can retain up to four, and displayed totals round half-up after comparison. |
| Individual prediction probability | 75%–100% by default. Input allows 0%–100% and uses inclusive bounds. The stored Builder applies a minimum effective floor of 75%, so a maximum below 75% yields no qualifying slips. |
| Matches per slip | At least one by default. A supplied maximum must be an integer at or above the minimum. The available distinct fixtures and search limits bound a build. |
| Reuse Matches | Off by default. Every slip contains distinct fixtures. Off also prevents reuse across the returned set. On allows a fixture to appear in multiple different slips. |
| Markets | The four base markets are selected by default with automatic outcome choice per family. Team goals is opt-in. Selected outcome lists restrict the permitted choices for that market. |

Markets include 1X2, double chance, BTTS, full-time match totals at 1.5/2.5/3.5/4.5/5.5 and the corresponding per-team totals. Each extended line needs a sealed forecast and an exact price for the relevant fixture, period, line and side. [Market definitions](../next-js/src/domain/slip-markets.ts), [Odds arithmetic](../next-js/src/domain/odds.ts), [Date and time rules](../next-js/src/domain/date-time.ts), [Prediction engine](prediction-engine.md).

## Build flow and result handling

1. The route checks content access. The native GET and enhanced form use the same rules. Free access lets visitors edit filters. The build control leads guests to login and signed-in restricted viewers to subscription access. Active entitlement, an allowed member policy, administrator access or confirmed paywall-off mode can grant full access. Access is checked again before returning a generated result. [Viewer access](../next-js/src/server/members/viewer-access.ts), [Gated reads](../next-js/src/server/members/gated-reads.ts), [Subscriptions](subscriptions.md).
2. With approved odds rights, the service consumes the shared database-backed Matches search allowance and reads up to 500 fixtures in a repeatable-read cohort. The query uses the configured competition scope, an open cycle and a scheduled fixture with a current forecast still before the five-minute publication deadline. It excludes unresolved lifecycle issues and known early starts. A final selected-fixture check verifies current schedule, cycle and availability and withholds slips affected by drift. [Service](../next-js/src/server/slips/slip-service.ts), [Cohort](../next-js/src/server/slips/slip-cohort.ts), [Search limiter](../next-js/src/server/matches/search-limit.ts), [Odds rights policy](../next-js/src/server/odds/public-odds-policy.ts).
3. Candidate picks come from the selected markets in the matching stored forecast, including usable published fallback sources. The search uses exact, eligible bookmaker prices for those outcomes, and legs can come from different bookmakers. Lower-priced variants can be considered when a bounded total makes them useful. The search prunes impossible price ranges, avoids repeated legs and caps the candidate list at 800, the search and batch work at 100,000 nodes each and the retained ranked combinations at 2,000. [Price reader](../next-js/src/server/slips/price-read.ts), [Combination search](../next-js/src/domain/slip-builder.ts).
4. The default search ranks by the conservative joint lower bound from the leg probabilities, then higher exact total odds and fewer legs. When reuse is off, a compatible-set search fills as much of the requested count as it can and prefers higher-ranked candidates among equally large sets. The page displays the returned set in average leg-probability order, 20 per page. The default web binding supplies no joint estimator, so an explicit whole-slip probability constraint produces `model-unavailable`. [Ranking](../next-js/src/domain/slip-builder.ts), [Model binding](../next-js/src/server/slips/joint-model.ts), [Pagination](../next-js/src/domain/slip-pagination.ts).

Missing odds, absent qualifying fixtures, feasible fixtures without matching combinations, exhausted rate limits and unavailable data have separate result states. The UI reports a smaller result set and indicates bounded search or partial fixture coverage. These states can depend on current stored evidence, odds rights or configuration. [Result states](../next-js/src/domain/slip-page.ts), [Service tests](../next-js/tests/slip-service.test.mjs), [Search tests](../next-js/tests/slip-builder.test.mjs).

On 26 November 2026, staging accepted valid desktop and mobile submissions and displayed **Odds unavailable**. Its configured profile had neither a public odds rights reference nor the corresponding approval. The service returned before reading fixtures. An isolated fixture with qualifying prices generated two slips on desktop and mobile, and a production diagnostic request also generated results. [Odds policy](../next-js/src/server/odds/public-odds-policy.ts), [Build service](../next-js/src/server/slips/slip-service.ts).

## State, saved filters and sharing

- Generated selections are transient page results. The build URL retains criteria, so submitting or reloading it can recalculate against current stored data. Live match-state polling uses the original cycle/revision identities for visible slips. It updates scores, phase and results. [Builder route](../next-js/src/app/_components/slips-route.tsx), [Match-state endpoint](../next-js/src/server/slips/slip-match-states.ts).
- An authenticated, unblocked account can manage up to ten filter presets without an active subscription. `GET` and `POST /api/account/slip-configurations` list or create, update, rename, delete and set a default. Names are unique per account and updates check revision numbers. Exact From/To remains in new presets, while legacy time-only presets are dated when loaded. The `SlipConfiguration` table holds criteria, names, revision and default state. [Preset API](../next-js/src/app/api/account/slip-configurations/route.ts), [Preset service](../next-js/src/server/slips/slip-configurations.ts), [Preset rules](../next-js/src/domain/slip-configurations.ts), [Prisma schema](../next-js/prisma/schema.prisma).
- Builder uses its image export flow for new personal slips. `POST /api/slips/number` can obtain a stable display number from a fingerprint without storing the selections. New canonical share links refer to published Best Slips. Previously issued private/shared snapshot links retain their original read path. [Number endpoint](../next-js/src/server/slips/slip-numbers-http.ts), [Sharing endpoint](../next-js/src/server/slips/shared-slips-http.ts), [Storage migration](../next-js/prisma/migrations/20261103120000_transient_slips_and_odds_bands/migration.sql).

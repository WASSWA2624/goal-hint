# UI implementation

## Application shells and routes

The Next.js App Router serves the shared web interface. The root loads the local Manrope font, the styled-components provider, the theme preference bootstrap and offline initialization. The locale layout validates the locale, supplies the app download catalog and resolves indexing policy for the request. [Root layout](../next-js/src/app/layout.tsx), [locale layout](../next-js/src/app/[locale]/layout.tsx), [style provider](../next-js/src/styles/provider.tsx).

Matches, Slips, Builder and Performance share a persistent layout. It keeps the header, mobile brand bar, bottom tabs, community invitation surface and skip link mounted as the selected route changes. Standalone pages use the same shell components. Desktop links and mobile tabs come from one destination list. Responsive navigation measures the available width, moves overflowing links into **More**, and keeps the current destination labelled. Account controls and the owner Dashboard entry follow the current session. [App navigation layout](../next-js/src/app/[locale]/(app-navigation)/layout.tsx), [public shell](../next-js/src/components/navigation/public-shell-chrome.tsx), [responsive navigation](../next-js/src/components/navigation/responsive-navigation.tsx), [session navigation](../next-js/src/components/navigation/session-navigation.tsx).

## Controls, appearance and feedback

- The styled-components registry flushes styles during server rendering. The shared provider resolves light or dark preference from the browser, falls back to the system preference, and synchronizes saved preference changes across browser tabs. A pre-paint script applies an explicit saved preference. Streamed UI boundaries hydrate against the server theme before following the resolved client theme. The provider publishes appearance metadata used by the Flutter host. [Style registry](../next-js/src/styles/registry.tsx), [theme preference](../next-js/src/styles/theme-preference.ts), [style provider](../next-js/src/styles/provider.tsx).
- Semantic theme tokens drive text, surfaces, borders, status colors, spacing and the radius scale. Global styles set the shared control height, with a pointer-based touch height. Buttons, inputs and single-choice menus reuse the labelled field, validation and focus treatments. Shared form rows arrange controls using the same sizing across layouts. [Theme](../next-js/src/styles/theme.ts), [global styles](../next-js/src/styles/global-style.tsx), [controls](../next-js/src/components/ui/controls.tsx), [control uniformity](../next-js/docs/control-uniformity.md), [corner radii](../next-js/docs/corner-radius.md).
- Filters use a shared dialog shell with a labelled title, scrollable content and Reset, Cancel or Apply actions where the flow supplies them. Native dialog support provides modal and Escape handling. Criteria forms can render their fields inline before enhancement. Market filters share a searchable child dialog and preserve choices while rows are filtered. [Criteria dialog](../next-js/src/components/ui/criteria-dialog.tsx), [filter dialog](../next-js/src/components/ui/advanced-filter-dialog.tsx), [market dialog](../next-js/src/components/ui/market-filter-dialog.tsx).
- Foreground navigation and pending content use the shared progress track below the active header. Next.js links mark real pending navigation, and content uses `aria-busy` or an `AppLoading` marker. Passive reads can opt out with `data-navigation-passive`. The track respects reduced-motion preferences. Individual panels supply their own validation, empty states or retry actions. [Navigation link](../next-js/src/components/navigation/navigation-link.tsx), [progress indicator](../next-js/src/components/navigation/navigation-progress.tsx).
- Account and owner record screens share a list and detail workspace. Desktop can show both panes with a resizable list. On compact layouts, selecting a record opens its detail view and Back restores the list context. Detail actions have a separate footer. Account section links use the same control style and provide a phone menu with section and member identity. [Record workspace](../next-js/src/components/admin/record-workspace.tsx), [account records](../next-js/src/components/members/account-records.tsx), [account workspace](../next-js/src/components/members/account-workspace.tsx).

## How UI updates and refreshes

Server rendering supplies the initial view and access level. Applied filters and paging can be represented in the URL. Drafts, open controls and transient results stay in the relevant component or route-scoped store. Matches uses its own Redux store and stored-data API adapter. Applicable Match Details uses a separate Redux request cache keyed by fixture and access. Best Slips, slip observations, checkout and live analytics each keep their own scoped state. [Client state contract](../next-js/src/state/README.md), [feed provider](../next-js/src/state/provider.tsx), [detail provider](../next-js/src/state/detail-provider.tsx), [Best Slips browse hook](../next-js/src/components/slips/use-best-slips-browse.ts), [slip match observations](../next-js/src/components/slips/slip-match-observations.ts).

| Surface | Trigger and visible update |
| --- | --- |
| Matches search, filters and pagination | The search input updates immediately. Typing waits 300 ms before the read, while Enter and Search can run it immediately. A newer search cancels the older request. The accepted list and its canonical URL update together. Outcome navigation can change the list while keeping confirmed period totals visible. Pagination checkpoints preserve list position and focus where the results still match. [Feed surface](../next-js/src/app/_components/feed-surface.tsx), [live search](../next-js/src/components/match/use-live-feed-search.ts), [pagination](../next-js/src/components/match/use-feed-pagination.ts), [performance summary](../next-js/src/components/match/feed-performance-summary.tsx). |
| Matches and applicable Match Details | A visible, online browser reads stored data every 20 seconds when a run is updating, a fixture is live or a scheduled kickoff is within 30 minutes. Quiet views use 60 seconds. The loop responds to visibility, connection, restored pages and calendar rollover. Matches also supports a foreground pull-to-refresh where the interaction permits it. Match Details merges fresh data into the accepted fixture and updates the rendered view when visible data changes. Historical revision inspection is separately rendered. [Refresh policy](../next-js/src/domain/live-refresh.ts), [browser refresh hook](../next-js/src/components/match/use-live-refresh.ts), [live details](../next-js/src/components/match/live-match-detail.tsx). |
| Live clock | Visible elapsed text uses a shared one-second browser ticker when the stored observation supports an estimate. The small clock text subscribes directly. Score, phase and observation time come from the stored snapshots on the refresh cycle. [Score and clock presentation](../next-js/src/components/match/score-presentation.tsx), [clock rules](../next-js/src/domain/match-clock.ts). |
| Best Slips browsing | Date, filter and page actions request the new cohort while the accepted content remains visible. The browser updates history after accepting the requested response. Visible, online finite-period views quietly poll the same query every 60 seconds. Access revocation clears protected content and triggers a server recheck. [Browse hook](../next-js/src/components/slips/use-best-slips-browse.ts), [Automatic slips](automatic-slips.md). |
| Slip observations | Builder and Best Slips use one polling loop per enabled list. It deduplicates visible legs by original fixture, market, outcome and forecast identity, then reads observations every 20 seconds through `/api/slips/match-states`. The provider pauses during hidden, offline or navigating states and retries with backoff. The accepted odds and initial selections remain the card's source for the slip, while scores, outcomes and availability update independently. [Provider](../next-js/src/components/slips/slip-match-refresh.tsx), [polling](../next-js/src/domain/slip-match-polling.ts), [observation contract](../next-js/src/domain/slip-match-refresh.ts). |
| Checkout and session | Visible checkout pages request fresh server state every 20 seconds and on focus, reconnect or return to visibility. After a mutation, checkout aborts and pauses background reads during its own fresh status request. Newly observed approval can refresh the account and access view. The shared session header also rechecks on focus, restored pages, visibility and its access deadline. [Checkout view](../next-js/src/components/members/checkout-flow.tsx), [checkout refresh](../next-js/src/components/members/checkout-refresh.ts), [member session](../next-js/src/components/members/member-session.ts). |
| Wallet and referral actions | After a wallet purchase or renewal-setting change, the account refreshes its server-rendered data and rechecks the shared member session. A successful referral appeal refreshes the reviews and the unread notification count. Controls keep submission state local while requests are pending. [Wallet controls](../next-js/src/components/members/credit-controls.tsx), [referral appeals](../next-js/src/components/members/account-referral-reviews.tsx), [Wallet and referrals](wallet-and-referrals.md). |
| Contact and Analytics | Contact checks visible pages every 15 seconds and reacts to focus and support-setting notifications across tabs. Live Analytics displays share one private 15-second poll while visible. Its live values update separately from the report charts and tables. [Contact view](../next-js/src/components/members/contact-page.tsx), [Analytics live store](../next-js/src/components/analytics/dashboard/live-report.ts). |
| Owner mutations | Editors apply the server's confirmed result and can request fresh route data using the owner refresh action. A failed refresh retains the current editor and reports a retry message. The server can redirect an expired owner session. [Owner refresh hook](../next-js/src/components/admin/use-admin-refresh.ts), [owner actions](../next-js/src/app/(owner)/actions.ts). |

Refresh paths use stable fixture or record keys and reuse unchanged snapshot branches where supported. Pending navigation and explicit retries expose accessible busy feedback. Scheduled polling keeps the progress bar quiet. Stale responses, expired access and errors are handled at the relevant boundary before a replacement view is accepted. Browser refreshes read application endpoints, while provider updates use separate worker jobs. [Structural sharing](../next-js/src/domain/structural-sharing.ts), [live data merge rules](../next-js/src/domain/live-refresh.ts), [progress indicator](../next-js/src/components/navigation/navigation-progress.tsx), [Fixtures and live data](fixtures-and-live-data.md).

If a document request fails or takes more than 15 seconds to return headers, the service worker can show the prepared connection page at the requested URL. **Try again** requests the same URL and preserves its filters. The offline cache holds the verified static connection page and its assets only. An open Matches view handles a stalled filter request separately by keeping the accepted rows and offering a retry for the requested filters. [Service worker](../next-js/public/offline-worker.js), [connection view](../next-js/src/components/offline/offline-view.tsx), [connection recovery](../next-js/docs/offline-startup.md).

## Component reuse and responsive layout

| Shared component | Where and how it is reused |
| --- | --- |
| Date strip, calendar and filter trigger | Matches and Best Slips share the date interface. Each caller supplies its cohort, date rules and filter commit handler. Matches can use the device browsing zone, while Best Slips uses Kampala reporting dates. [Date controls](../next-js/src/components/match/feed-dates.tsx), [Matches filters](../next-js/src/components/match/feed-filters.tsx), [Best Slips filters](../next-js/src/components/slips/best-slips-filters.tsx). |
| Form controls, dialogs and layout primitives | Shared buttons, input feedback, control rows, select menus and dialog surfaces keep labels, focus and control sizing consistent across filters, checkout, account and owner pages. Builder and its saved filters use the same field definitions. [Controls](../next-js/src/components/ui/controls.tsx), [row layout](../next-js/src/components/ui/control-layout.ts), [select menu](../next-js/src/components/ui/select-menu.tsx), [slip criteria fields](../next-js/src/components/slips/slip-criteria-fields.tsx). |
| Match and slip presentation | `MatchCard` adapts the same fixture data to a compact tile or desktop row and can show a gated preview or an accessible selection. `SlipCard` and `SlipCardSummary` select between compact and desktop layouts while sharing odds, outcome and share behavior. [Match card](../next-js/src/components/match/match-card.tsx), [slip card](../next-js/src/components/slips/slip-card.tsx), [share action](../next-js/src/components/slips/slip-share-action.tsx). |
| Performance summaries and pagination | The same summary component serves matches and slips with caller-provided counts and result actions. Its grid responds to the available container width. Shared numbered pagination receives the count and navigation handler or links from the feature. [Performance summary](../next-js/src/components/performance/performance-summary.tsx), [numbered pagination](../next-js/src/components/ui/numbered-pagination.tsx). |

Both themes use the same viewport geometry. The main desktop breakpoint is `64rem`, with compact layouts below it. The media helpers also expose phone and wide layouts, plus pointer and hover conditions. CSS handles layout changes where the markup can be shared. Components that need a different presentation, such as slip cards, use `useDesktopLayout` with a compact server fallback and subscribe to the same desktop media query after hydration. Bottom navigation and compact record panels account for safe-area insets. Desktop record panes and navigation use width measurement and resize controls. [Theme media helpers](../next-js/src/styles/theme.ts), [theme geometry](../next-js/src/styles/theme-foundation.ts), [desktop layout hook](../next-js/src/components/ui/use-desktop-layout.ts), [shell styles](../next-js/src/components/navigation/shell-styles.tsx), [record workspace](../next-js/src/components/admin/record-workspace.tsx).

## Flutter host

Flutter opens the configured web origin in a native browser surface. It provides startup, connection recovery, appearance synchronization and platform sharing or download bridges. Supported shared-slip links load in the retained browser session. Checkout navigation can hand an approved off-origin hosted payment page to the system browser. The Next.js routes own the account, checkout and football UI and enforce their server rules. [Flutter shell](../flutter/lib/web/web_app_shell.dart), [appearance and deep links](../flutter/lib/app.dart), [navigation policy](../flutter/lib/web/navigation_policy.dart), [Payments](payments.md).
